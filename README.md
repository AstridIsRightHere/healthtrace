# 康迹 HealthTrace

帮助成年患者及获授权家属整理病历照片，通过 OCR 辅助提取、人工确认和趋势展示，为就医沟通准备清晰记录的个人健康记录项目。

## 当前阶段

本项目处于**前期文档阶段**，目前包含 30 份编号文档（00～29）及文档索引，覆盖需求、设计、工程规划和论文草稿。第二阶段文档已通过评审；尚未编码、执行产品测试或部署，无已实现功能或实验结果可供声明。

docs/ 下的部分文档写于 Git 初始化之前，其中“尚未初始化 Git”等描述保留为编写时的历史状态；当前本地仓库已初始化，详见本 README 的“当前阶段”一节。进入编码阶段仍需项目发起人明确授权。

## 技术栈

以下为规划基线和建议，尚未创建应用工程或锁定精确版本。

| 层次 | 规划与状态 |
| --- | --- |
| 前端 | 已确认 Vue PWA；建议 Vue 3、TypeScript、Vite |
| 后端 | 已确认 Spring Boot；建议模块化单体，JDK 与 Spring Boot 版本组合待定 |
| 数据库 | 已确认 MySQL；具体受支持版本待定 |
| 图表与数据访问 | 建议 ECharts；MyBatis 为候选，待评审确认 |
| OCR 与文件存储 | 计划采用可替换 OCR 适配器及私有对象存储，供应商与处理条款待定；OCR 结果需人工逐项确认 |
| 交付 | 规划使用 GitHub Actions，初期人工批准发布；部署方式待定 |

详细理由、替代方案与待确认事项见 [技术选型建议](docs/13-技术选型建议.md)。

## 路线图

MVP 规划围绕邀请制、一账号一患者档案、报告上传与确认、指标趋势、就诊时间线及删除撤回流程展开。后续版本候选包括多档案、协作、PDF、月历和结构化处方；具体范围与优先级以 [版本路线图](docs/21-版本路线图.md) 为准。

阶段评审、编码前决策和实施安排见 [里程碑与迭代计划](docs/11-里程碑与迭代计划.md) 与 [待决策清单](docs/23-待决策清单.md)。文档批准不等于编码批准。

## 合成数据声明

开发、测试及公开演示仅使用自造合成数据。公开仓库仅用于文档、将来的代码和合成示例，不应包含真实病历、可识别个人身份的健康资料、数据库导出或密钥。任何未来真实资料试用，均须先满足文档规定的授权、安全、隐私与恢复验收门槛。

## 非医疗用途声明

HealthTrace 定位为记录整理与就医沟通辅助工具，不提供诊断、治疗、用药或处方建议，不替代医生的专业判断。OCR 辅助提取可能出现错误，必须由使用者核对确认；趋势展示不构成医学结论。
