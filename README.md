# 康迹 HealthTrace

帮助成年患者及获授权家属整理病历照片，通过 OCR 辅助提取、人工确认和趋势展示，为就医沟通准备清晰记录的个人健康记录项目。

## 当前阶段

本项目已进入**编码阶段**（2026-10-24 起），目前仅完成前后端**工程骨架**，尚无业务功能、产品测试或部署，无已实现功能或实验结果可供声明。31 份编号文档（00～29、31）及文档索引覆盖需求、设计、工程规划和论文草稿，第二阶段文档已通过评审。

docs/ 下的部分文档写于 Git 初始化或编码授权之前，其中“尚未初始化 Git”“不创建工程”等描述保留为编写时的历史状态。

## 本地启动

环境要求：JDK 21、Maven 3.9+、Node.js 22.18+（当前部分依赖要求 `^22.18.0 || >=24.11.0`）、Docker Desktop。依赖与缓存放在 D 盘，约定见 [29 环境配置说明](docs/29-环境配置说明.md)。

1. 准备环境变量：复制 `.env.example` 为 `.env`，填写本机自定的值。`.env` 不进入 Git。
2. 启动 MySQL：

   ```bash
   docker compose up -d
   docker compose ps          # 等待 healthy
   ```

3. 启动后端（变量缺失时会直接启动失败，这是预期行为）：

   ```bash
   cd backend
   # 需在当前 shell 中导出 SPRING_PROFILES_ACTIVE=dev、DB_URL、DB_USERNAME、DB_PASSWORD
   mvn spring-boot:run
   ```

4. 启动前端：

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

构建验证：`frontend` 下 `npm run build`；`backend` 下 `mvn -DskipTests package`。

## 路线图

MVP 规划围绕邀请注册邮箱验证、单账号单患者档案、图片/PDF上传、OCR草稿或手填逐项确认、18项字典与临时指标、分单位可比组图、就诊与修改留痕、列表移除/彻删/注销/人工撤回，以及 DEC-015 的指标归并提示、确认/撤销/分开展示展开。性能目标按 DEC-009 为首屏≤2s（4G中端手机）、API平均≤500ms（家庭网络单用户）、OCR草稿≤30s（正常网络单页图片）、单指标100点图表≤1s、100条记录列表≤1s；这些均未实现或测试。后续 v1.1 包括多档切换、患者接管、自助撤回、邮箱变更、PDF批量上传、月历、临时指标手动归并、疾病/检查手填、匿名计数（候选，默认关闭）、完整老年人模式、关键数值TTS、数据导出与就医摘要；MVP 可访问性按 DEC-018 包含主题/四档字号、趋势表格与客观描述、读屏核心流程等基线。v2 包括多人协作、处方/药物/数量、自动单位换算和自建OCR，声音化与多语言/方言为长期候选。具体范围与优先级以 [版本路线图](docs/21-版本路线图.md) 为准。

阶段评审、编码前决策和实施安排见 [里程碑与迭代计划](docs/11-里程碑与迭代计划.md) 与 [待决策清单](docs/23-待决策清单.md)。文档批准不等于编码批准。

## 合成数据声明

开发、测试及公开演示仅使用自造合成数据。公开仓库仅用于文档、将来的代码和合成示例，不应包含真实病历、可识别个人身份的健康资料、数据库导出或密钥。任何未来真实资料试用，均须先满足文档规定的授权、安全、隐私与恢复验收门槛。

## 非医疗用途声明

HealthTrace 定位为记录整理与就医沟通辅助工具，不提供诊断、治疗、用药或处方建议，不替代医生的专业判断。OCR 辅助提取可能出现错误，必须由使用者核对确认；趋势展示不构成医学结论。
