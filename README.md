# 康迹 HealthTrace

帮助成年患者及获授权家属整理病历照片，通过 OCR 辅助提取、人工确认和趋势展示，为就医沟通准备清晰记录的个人健康记录项目。

## 当前阶段

本项目处于 **MVP 开发后期**（2026-10-24 进入编码，截至 2026-11-12 已合入 PR #1～#29），核心数据闭环已在开发环境跑通，尚未部署或开展真实用户试用，主验收 TC 尚未执行。详细盘点见 [34 项目进度与阶段规划报告](docs/34-项目进度与阶段规划报告.md)。

已合入 main 的功能：

- 账号：邀请制注册、邮箱验证、登录与失败锁定、密码找回、账号注销（FR-001/002/017）
- 患者档案：单账号单患者，授权声明，所有资源越权统一 404（FR-003、NFR-001）
- 报告上传：多图/PDF、拖拽上传、原件与预览图双存、重复提示、报告种类（检验/影像/其他）、编辑标题与检查日期（FR-004/005）
- OCR 识别与逐项确认：百度医疗检验报告单识别、异步任务与有界重试、识别原文加密存储、OCR 同意记录、手动录入（FR-006/007/015）
- 指标：18 项标准字典、临时指标（字典外项目可设为本档临时指标并关注，同名同单位自动归并）、关注指标与拖动排序、按可比组的趋势图与结构化表格、报告对比（FR-008/009 部分、FR-010/011）
- 首页、档案、时间线：关注指标卡、待处理报告、最近就诊；档案按种类筛选；就诊记录与报告双向关联（FR-012/013）
- 修改留痕与审计：报告修改与指标级历史、审计事件（FR-014、NFR-010）
- 删除：列表移除与回收站（首页待处理与报告详情均可移入）、彻底删除与删除账本（FR-016）
- 应用导航：移动端底部 4 Tab（首页/档案/时间线/我的），桌面端（≥960px）左侧侧边栏

MVP 尚未完成：DEC-015 异名同单位强提示与手动归并/撤销（FR-009）、人工撤回授权渠道（FR-017）、管理员字典/邀请码维护（FR-018）、读屏真机测试（NFR-006）；以及部署、备份恢复、供应商合同等上线前置条件。见 [版本路线图](docs/21-版本路线图.md) 第 7 节。34 份编号文档（00～29、31～34）及文档索引覆盖需求、设计、工程规划、进度报告和论文草稿。

## 本地启动

环境要求：JDK 25、Maven 3.9+、Node.js 24.11+、Docker Desktop。依赖与缓存放在 D 盘，约定见 [29 环境配置说明](docs/29-环境配置说明.md)。

1. 准备环境变量：复制 `.env.example` 为 `.env`，填写本机自定的值。`.env` 不进入 Git。
2. 启动 MySQL：

   ```powershell
   docker compose up -d
   docker compose ps          # 等待 healthy
   ```

3. 启动后端：

   ```powershell
   .\start-dev.ps1            # 从 .env 注入变量（不打印值），检查 MySQL 健康后以 dev profile 启动
   ```

   脚本只在当前进程中注入变量；缺少必需变量时列出变量名并退出。dev profile 下会话 Cookie 关闭 `Secure`，以便在 `http://localhost` 下保持登录；其他环境保持 `Secure`。

4. 启动前端（另开一个终端）：

   ```powershell
   .\start-frontend.ps1       # 首次运行自动 npm ci，之后启动 Vite，/api 代理到 127.0.0.1:8080
   ```

质量检查：

| 位置 | 命令 |
| --- | --- |
| `frontend` | `npm run lint`、`npm test`（Vitest）、`npm run build` |
| `backend` | `mvn verify`（Web 层与 Mockito 单元测试 + Testcontainers MySQL 8.4 集成测试，需本机 Docker；不连接本地开发库） |

以上检查在 PR 时由 [CI](.github/workflows/ci.yml) 自动运行。

## 路线图

MVP 规划围绕邀请注册邮箱验证、单账号单患者档案、图片/PDF上传、OCR草稿或手填逐项确认、18项字典与临时指标、分单位可比组图、就诊与修改留痕、列表移除/彻删/注销/人工撤回，以及 DEC-015 的指标归并提示、确认/撤销/分开展示展开。性能目标按 DEC-009 为首屏≤2s（4G中端手机）、API平均≤500ms（家庭网络单用户）、OCR草稿≤30s（正常网络单页图片）、单指标100点图表≤1s、100条记录列表≤1s；性能阈值尚未实测，各项实现进度见路线图第 7 节。后续 v1.1 包括多档切换、患者接管、自助撤回、邮箱变更、PDF批量上传、月历、临时指标手动归并、疾病/检查手填、匿名计数（候选，默认关闭）、完整老年人模式、关键数值TTS、数据导出与就医摘要；MVP 可访问性按 DEC-018 包含主题/四档字号、趋势表格与客观描述、读屏核心流程等基线。v2 包括多人协作、处方/药物/数量、自动单位换算和自建OCR，声音化与多语言/方言为长期候选。具体范围与优先级以 [版本路线图](docs/21-版本路线图.md) 为准。

阶段评审、编码前决策和实施安排见 [里程碑与迭代计划](docs/11-里程碑与迭代计划.md) 与 [待决策清单](docs/23-待决策清单.md)。文档批准不等于编码批准。

## 合成数据声明

开发、测试及公开演示仅使用自造合成数据。公开仓库仅用于文档、将来的代码和合成示例，不应包含真实病历、可识别个人身份的健康资料、数据库导出或密钥。任何未来真实资料试用，均须先满足文档规定的授权、安全、隐私与恢复验收门槛。

## 非医疗用途声明

HealthTrace 定位为记录整理与就医沟通辅助工具，不提供诊断、治疗、用药或处方建议，不替代医生的专业判断。OCR 辅助提取可能出现错误，必须由使用者核对确认；趋势展示不构成医学结论。
