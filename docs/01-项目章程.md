## 本阶段目标与产出

目标：为个人项目确定愿景、范围、责任与成功标准。产出：本章程及关联的需求、设计、工程与研究文档。下一步：评审第二阶段，再获得明确的“进入编码阶段”授权。

## 愿景与定位

项目：康迹（HealthTrace）。通过保存病历照片、OCR 辅助提取、人工确认和趋势展示，帮助长期就医的成年患者及家属整理记录、准备医生沟通。提供记录工具，不提供诊断、治疗或用药建议。

主要用户是为父母管理记录的成年子女；其次是成年患者本人、配偶及其他获授权的成年代管者。操作者账号与患者档案分开；首版每账号只允许一份患者档案，数据设计支持未来多份。

## 目标、范围与非目标

| 类别 | 内容 |
| --- | --- |
| 产品目标 | 完成照片到确认记录、指标趋势与就医时间线闭环 |
| 工程目标 | 学会数据库与后端、Issue/分支/PR、自审、测试、CI、部署、备份恢复 |
| 研究目标 | 保留需求追踪、决策依据及可复现实验资料，形成毕业论文材料 |
| MVP 范围 | 邀请制账号、邮箱验证、一份患者档案、图片与PDF报告（DEC-008）、OCR/手填、确认、18项标准字典及临时指标、关注图表、就诊时间线、删除注销与人工撤回 |
| 非目标 | 社交、评论、推荐、在线问诊、开药、诊断建议、医生专业系统；微服务、K8s、复杂灰度与监控平台 |
| 后续范围 | 多档案、协作、批量报告、月历、结构化处方等见版本路线图 |

“不泄露隐私”是安全目标，不能宣称任何系统绝对零风险；以权限隔离、最小收集、供应商审查和删除恢复测试落实。

## 成功标准

1. 合成数据下通过全部 MVP P0 验收，并保留执行证据；未执行测试不能写为通过。
2. 用户能完成上传、纠正、确认、查趋势、关联就诊和删除；失败可恢复，草稿不进入正式图表。
3. 真实资料试用前满足验收文档全部安全、合规与恢复门槛；先自己验证，再邀请2～3位家人，不公开推广。
4. 年度现金支出上限500元；采购前核实首年与续费。若无法满足安全和预算，则维持合成数据演示并调整范围，不能降级隐私门槛。
5. 公开仓库只包含文档、将来的代码和合成示例，无真实病历、数据库导出和密钥。
