# 07 页面清单与结构图

## 目标、产出与下一步

目标：温馨且能清楚核对数据，减少代管者认知负担。产出：页面职责、元素、导航和版本。下一步：先做低保真设计与任务走查，不编写页面代码。

## 全局导航（已实现）

登录后页面统一挂在 `AppLayout` 布局下，提供 4 个一级 Tab：

| Tab | 路由 | 内容 | 归属的二级页面 |
|---|---|---|---|
| 首页 | `/` | PG-004 首页 | 趋势详情 `/trends` |
| 档案 | `/records` | 已确认报告列表（PG-008），按种类筛选（全部/检验/影像/其他，`?kind=`），影像/其他显示结论摘要；上传入口 | 报告对比 `/reports/compare` |
| 时间线 | `/timeline` | 合并时间轴（PG-011）：就诊与未关联就诊的报告按年分组、日期倒序；就诊卡片列出关联报告 | 就诊记录 `/visits` |
| 我的 | `/me` | 账号信息、关注指标管理（含本档临时指标）、显示设置、回收站、设置与隐私、隐私政策、数据授权说明、退出登录 | 显示设置 `/display`、回收站 `/recycle-bin`、设置 `/settings` |

- 移动端（<960px）：底部固定 Tab 栏，高度 64px + 安全区；悬浮上传按钮与提示条位于 Tab 栏之上，内容区底部预留导航高度。
- 桌面端（≥960px）：左侧固定侧边栏（232px，品牌 + 4 项 + “上传报告”按钮），隐藏悬浮上传按钮。
- 二级页面高亮其所属 Tab（路由 `meta.tab`），并提供返回所属 Tab 的链接；触控目标不小于 44×44 CSS px，当前 Tab 带 `aria-current="page"`。
- 登录、注册、邮箱验证、档案建立、上传与核对草稿为专注流程，不显示全局导航。
- 退出登录、关注指标管理、回收站入口已由首页移至“我的”。

### 报告种类（2026-11-05 已实现）

- 上传页 PG-005 先选报告类型：检验报告（STRUCTURED，走 OCR/手动录入 → 逐项核对确认）、影像报告（IMAGING：超声/CT/X 光/核磁）、其他报告（UNSTRUCTURED：病历、诊断证明）。`/reports/new?kind=IMAGING` 可预选。
- 影像/其他报告只保存原件与结论/说明文本（≤4000 字），上传完成后点“完成归档”直接成为已确认报告并跳转 `/records?kind=…`，不调用第三方 OCR。
- 报告详情对影像/其他报告显示结论与已关联就诊，不显示检验结果表；就诊与报告的关联在就诊记录页维护。
- 视觉规范见 [32 UI 原型与设计规范](32-UI原型与设计规范.md)，使用说明见 [33 用户操作手册](33-用户操作手册.md)。

### 显示设置、隐私说明、PWA 与临时指标（2026-11-12 已实现）

- 显示设置 `/display`（PG-013 一部分）：主题“跟随系统 / 浅色 / 深色”，字号“小 14 / 标准 16 / 大 20 / 特大 24 px”；保存在本机 localStorage（`ht.theme`、`ht.fontSize`），首屏渲染前应用，不上传服务器。全站字号使用 rem，随根字号缩放。
- 隐私政策 `/privacy`、数据授权说明 `/data-authorization`：公开页面，未登录也可在注册前阅读；“我的”页提供入口。内容包括收集范围、加密方式（邮箱与 OCR 原文 AES-256-GCM、密码 BCrypt；照片与 PDF 写盘前 AES-256-GCM 加密）、百度 OCR 的触发条件与处理方式、拒绝 OCR 可手动录入、撤回授权与注销方式；人工撤回联系方式待 DEC-016。
- PWA：manifest（名称、图标、standalone），Android/桌面 Chrome 在可安装时显示“添加到主屏幕”提示条，iOS Safari 显示“分享 → 添加到主屏幕”说明；关闭后 30 天内不再提示。Service Worker 只预缓存构建产物（JS/CSS/HTML/图标），`/api/`、Swagger 不走 SPA 回退，未配置运行时缓存，任何接口响应与报告原图都不进入缓存。新版本可用时提示刷新。
- 临时指标（PG-006 / PG-009）：已确认检验报告的核对页列出没有映射到标准指标的结果，可一键“设为临时指标并关注”；同档案同名同单位的结果自动归入同一临时指标（DEC-015）。临时指标在首页关注卡、关注管理弹窗和趋势页（标记“临时指标”）中可用。异名同单位的强提示、手动合并/分开与撤销尚未实现。
- 首页待处理（PG-007）：每条提供“继续/重新识别”“移入回收站”“彻底删除”；移入后显示可去回收站恢复的提示。

## 交互与隐私原则

MVP按 DEC-018 采用 WCAG 2.2 AA 基线：文本对比度至少 4.5:1，支持 200% 缩放、可见焦点、避免冗余输入并支持自动填充，提供一致的帮助入口；项目触控目标基线为至少 44×44 CSS px（这是项目更严格基线，不宣称 WCAG AA 本身要求该尺寸）。颜色不得作为唯一信息编码，异常同时提供文字/符号。主题支持浅色、深色、跟随系统；字号提供 14、16（默认）、20、24 px。

每张趋势图可切换为结构化表格，列出日期、数值、单位及参考范围。自动文字描述只陈述客观数据，不作好转或恶化等医学判断；同单位但属于不同可比组的数据不得被描述为跨组趋势。表单错误提供可见文本并通过 aria-live 通知。VoiceOver 和 TalkBack 均须覆盖上传、核对、趋势核心流程。

MVP 指标归并规则：同一档案内同名同单位自动合并；同档案内异名同单位时显示归并依据和归并前后预览，由用户选择合并或暂不合并，操作可一键撤销；同名不同单位不换算、不自动合并，展示风险、原报告并可手动分开展示；跨档案永不合并。手动合并、分开展示及撤销均写入 AUDIT_EVENT 审计事件。MVP 提供自动归并、提示确认、撤销及分开展示；更完整的手动归并能力属于 v1.1。此处“同名同单位自动合并”是合并同一档案内重复出现的指标/别名指向，不是合并报告或检验记录。

v1.1 完整老年模式包括简化分步、关键数值 TTS、可选 Web Speech 输入、PDF/CSV 就医摘要导出、照顾者上下文引导及可选 WebAuthn。v2 候选为声音化与多语言/方言。以上是设计目标，未实现/未测试前不得表述为已交付或已验证。

上传和保存后明确显示“已上传/待确认/已确认”，避免将 OCR 成功误认正式保存。照片放大便于核对。不展示诊断建议或广告。移动浏览器可能中断上传，不承诺后台同步。退出和页面切换后不留下敏感缩略图缓存，通知/邮件不暴露病情。
