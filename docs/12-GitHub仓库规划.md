# 12 GitHub仓库规划

## 目标、产出与下一步

目标：公开学习和协作过程，确保资料能作为第一批提交评审。产出：目录、分支、模板与README规划。下一步：用户明确授权Git操作后才初始化、创建分支和提交；本文不含命令，当前未初始化Git。

## 基本建议

仓库名建议healthtrace；公开仓库。默认分支main受保护，开发在文档/功能/修复分支，例如docs/phase-2-planning、feat/report-confirmation，PR自审后合入。无第二位审阅者时不伪称完成独立审查。使用Issue关联FR/NFR、TC与ADR。个人项目不强制长期develop分支，减少合并成本；以后多人协作再评估。

建议MIT许可证：便于学习和复用、义务清晰；替代Apache-2.0提供明确专利条款但更长，GPL-3.0有衍生分发义务。License是DEC-010，确认前不创建正式许可证；软件许可不授权病历/个人信息，也不保证第三方字体/图标/依赖可任意使用。

## 提交与PR治理

提交类型建议docs/feat/fix/test/refactor/chore，标题表达目的并关联Issue；具体见22。初始文档提交不夹带代码。分支保护建议禁止强推、要求CI通过、PR合并；是否可用取决账号与仓库设置。每次Git操作先说明影响和回退方法，再等确认；不建议直推main。发布使用经测试的版本标签，回滚采用已验证产物与数据库兼容方案。

安全问题走私密渠道，不把漏洞利用细节、真实报告或邮箱贴公开Issue。误提交密钥先撤销轮换，再处理历史；仅删除当前文件不能消除历史泄露。
