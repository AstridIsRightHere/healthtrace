# 21 版本路线图

> 文档性质：设计阶段规划。文中功能均为计划，不代表已经实现或完成验证。版本与工期是估计，实际发布取决于验收、合规和预算。

## 1. 目标与资源边界

HealthTrace 面向有自主授权能力的成年人，以及受本人授权代管的成年子女、配偶，帮助整理历史检验报告并查看个人指标变化。系统不提供诊断、用药或治疗建议。MVP 采用 Vue PWA、Spring Boot 单体和 MySQL；技术版本系列已由 DEC-012 于 2026-10-20 确认，基线见 13；补丁版本、兼容性和维护周期在编码前核验。

投入假设为每周 8–12 小时，年度总预算不超过 500 元。首轮规划约 3–5 个月，仅为估计，不构成日期或交付承诺；每个迭代回顾，每 4 周重新检查范围、成本和风险。若真实报价不能满足预算，应缩小范围或延后上线，不能省略隐私和恢复要求。

## 2. 版本边界

| 版本 | 计划范围 | 验收重点 |
| --- | --- | --- |
| MVP | 邀请码、邮箱密码及邮箱验证；单账号单患者；本人或经授权家属代管；JPEG/PNG/HEIC/PDF 上传（DEC-008）、OCR 草稿、手填、人工逐项确认、指标图表、就诊时间线、审计、待处理、删除与人工撤回渠道 | 从合成报告到正式结果和图表的完整闭环；隔离、权限与删除符合要求 |
| v1.1 | 多档案创建和切换、邮箱变更、PDF 批量上传及批量报告、同日结果专门展示、月历、临时指标手动归并、自助撤回和解除代管、患者接管、疾病/检查手填、完整老年人模式与关键数值语音播报、数据导出与就医摘要 | 在明确授权和数据归属下增强体验；接管核验等独立依赖仍须确认 |
| v2 | 多人协作、处方/药物/数量、自动单位换算、自建 OCR | 先解决授权冲突、结构化来源、转换可追溯性和数据使用合法性，再评估实现 |

匿名计数仅是 v1.1 的候选研究项，默认关闭，不因汇总或去标识就断言为匿名。自建 OCR 学习也不构成患者数据训练授权。

### 功能版本归属总表（DEC-011，2026-10-20 已确认）

| 版本档位 | 已确认的功能归属 |
| --- | --- |
| **MVP（核心闭环必需）** | 邀请注册+邮箱验证、单患者档案、图片+PDF 上传、OCR 草稿+手填、逐项确认、18 项字典+临时指标关注、分单位分可比组图表、基础就诊时间线、修改留痕、列表移除+彻底删除、注销+人工撤回渠道 |
| **v1.1（体验增强）** | 多档案切换、患者接管、自助撤回授权、邮箱变更、PDF 批量上传、月历视图、临时指标手动归并、疾病/检查手填、匿名计数（候选）、完整老年人模式、关键数值语音播报、数据导出与就医摘要 |
| **v2（高风险/高成本）** | 多人协作、处方/药物/数量、自动单位换算、自建 OCR |

此表确认功能归属，不确认供应商、字典内容、接管核验或匿名分析已获准启用；相关独立 DEC 仍有效。MVP 的图片+PDF 上传指一份报告的文件集合，v1.1 PDF 批量上传增强不取消 MVP PDF 支持；临时指标 v1.1 完整手动归并工具不推迟 DEC-015 的 MVP 自动归并、强提示后的用户确认/撤销及分开展示。疾病/检查仅手填已知事实，处方/药物/数量不进入 MVP，不生成医疗建议。

### 可访问性版本边界（DEC-018，已确认）

- **MVP**：WCAG 2.2 AA，文本对比度≥4.5:1、项目触控基线≥44×44 CSS px、200% 缩放、焦点可见、已知信息自动填充以避免冗余输入、帮助入口位置一致；浅色/深色/跟随系统主题；14/16（默认）/20/24px 四档字号；非颜色编码；每个趋势图的日期/数值/单位/参考范围表格与自动客观文字描述；表单文字错误+aria-live；VoiceOver/TalkBack 核心流程可用。44px 是项目更严格要求，不误作 AA 本身的最低触控尺寸。
- **v1.1 完整可访问性 / 老年人模式**：简化分步（一次只问一件事）、关键数值 TTS、可选 Web Speech API 语音输入、PDF/CSV 导出及就医前摘要、区分本人/代管上下文的照顾者辅助引导、可选 WebAuthn 生物识别登录。
- **v2 / 长期候选**：图表声音化（sonification）、多语言 / 方言支持；候选不构成必交付承诺。

图表描述仅表达已确认、同单位同可比组事实，按各报告参考范围描述，不用“好转”“恶化”等判断；不能把确认版本表或基线当作已实现/测试证据。

## 3. MVP 功能与规则

- FR-001–FR-003：邀请验证、登录恢复、档案授权。未验证邮箱可登录，但不能真实上传或使用找回功能；人工邮件核实不得绕过验证。MVP 一账号一患者，数据库为未来多档案准备，画像仅影响文案，不赋予权限。
- FR-004–FR-009：图片与 PDF 可组成一份报告，按 DEC-008 限制为单文件 25 MiB、单报告合计最多 20 个文件、单用户初始 1 GiB；客户端图片长边压缩至 2048 px，保留原始文件和压缩预览图，支持历史补录；重复候选经用户处理；OCR 结果先进入草稿，逐项确认后形成正式数据。识别失败进入待处理，拒绝 OCR 可手填；原图与 OCR 审计按数据生命周期保留。18 项字典内容待 DEC-001 核实，未映射项可确认成临时指标，支持搜索、关注和排序；按 DEC-015，同名同单位同档案自动归并，异名同单位同档案强提示依据与前后图表预览，用户决定合并/暂不合并且可一键撤销；同名不同单位不推荐换算不自动合并，提示风险并可查原始报告、手动分开展示；跨档案永不合并，手动合并/分开及撤销写入 AUDIT_EVENT。
- FR-010–FR-011：仅正式数据进入图表；按单位分开，不自动换算，方法与标本差异分别分组。按真实检查时间提供 7 天、30 天、1 年、5 年及自选区间。范围判断使用报告自己的参考范围；前值为零不计算百分比，仍可计算绝对差；同日先后不明时不计算结果之间增减。非精确结果进入列表，单点展示空态说明，不插值。
- FR-012–FR-015：首页显示问候和昵称；本人显示“我的指标”，代管显示被管理者昵称，没有昵称则为“家人”。默认关注 WBC、HGB、PLT、ALT、AST、肌酐；展示待处理徽标、最近 1–3 条就诊和固定可见的上传入口。就诊日期、医院、备注手填，报告检查日可不同于就诊日；修改留下审计。
- FR-016–FR-018：区分列表移除与彻底删除；注销与撤回授权有人工办理说明。家属作授权声明并记录时间戳，管理员默认不能查看健康内容。开发阶段只使用自造合成数据。

## 4. 建议迭代安排

排期以[11 里程碑与迭代计划](11-里程碑与迭代计划.md)为主。本表只描述按能力分组的工作包，其中缓冲/试用对应11中的I5，不能把两表时间相加。

| 迭代 | 建议用时 | 目标产出 | 完成判据 |
| --- | --- | --- | --- |
| 0：边界与准备 | 1–2 周 | 确认需求、数据分类、DEC 阻塞项与合成样例 | 编码前决策有结论或明确延期范围 |
| 1：身份与档案 | 2–3 周 | 邀请、验证、登录恢复、单档授权闭环 | TC-001–TC-003 与隔离检查通过 |
| 2：报告处理 | 3–4 周 | 多图报告、OCR 草稿、拒绝 OCR 手填、确认和待处理 | TC-004–TC-009、TC-015 覆盖成功和失败路径 |
| 3：查看与追踪 | 2–3 周 | 图表、参考范围、首页和就诊时间线 | TC-010–TC-014 验证时间、单位与异常结果边界 |
| 4：治理与发布准备 | 3–4 周 | 两类删除、注销撤回、管理边界、恢复演练和移动端验收 | TC-016–TC-018 及 TC-101–TC-112 满足已批准阈值 |
| 缓冲与复盘 | 2–4 周 | 修复、文档更新、预算复核 | 八项上线门槛与境内合规准备均通过 |

各阶段可交叠但不能跳过前置决策；若超过每周可投入时间，则重新估算，不依靠压缩验证保持日期。

## 5. 发布门槛

上线前必须有可核查证据覆盖以下八项：邮箱验证、未验证账号限制、人工撤回说明、隐私与 OCR 说明、恢复演练、列表移除与彻底删除、移动浏览器适配、权限隔离。八项通过并不替代境内供应商合同、数据不训练约定和留存边界、有效同意、备案及其他适用合规评估。

对应 NFR-001–NFR-012 的验收采用 TC-101–TC-112，DEC-009 已于 2026-10-20 确认首屏≤2 秒（4G、中端手机）、API 平均≤500ms（家庭网络、单用户）、OCR 草稿≤30 秒（正常网络、单页图片）、图表≤1 秒（单指标 100 点）、列表≤1 秒（100 条）；按 TC-105 记录环境与实测结果，OCR 准确率及样本方法仍须细化，不能以“后续补测”代替发布证据。
