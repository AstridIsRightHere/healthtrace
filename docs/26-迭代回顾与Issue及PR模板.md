# 26 迭代回顾与 Issue 及 PR 模板

> 以下为文档内可复制的 Markdown 文本模板，尚未接入任何仓库自动化。只保存在 docs，不创建 .github 文件，不执行 Git 操作，不包含代码运行片段或配置模板。

## 1. 使用规则

每个迭代结束时回顾，每 4 周检查全局范围、预算、时间投入、决策和发布风险。每周投入假设为 8–12 小时，首轮 3–5 个月是估计，年度预算不超过 500 元须以实际报价检查。

公开 Issue 与 PR 只包含文档、代码及自造合成数据。不得提交真实报告、改名后的患者资料、图片、邮箱全文、检查数值、密钥或认证凭据。所有 Git 操作先解释目的和影响并取得用户确认，不直接向 main 推送。

功能编号 FR-001–FR-018 对应 TC-001–TC-018，非功能编号 NFR-001–NFR-012 对应 TC-101–TC-112；决策使用 DEC-001–DEC-025，架构理由使用 ADR-001–ADR-014。未验证的条目不得打勾或写成通过。

## 3. 功能或文档 Issue 模板

### 问题与目标

描述具体使用场景、当前缺口、预期结果和影响对象。说明属于 MVP、v1.1、v2 或仅候选。

### 范围与追踪

- 纳入范围：待填写。
- 排除或延期范围：待填写。
- 关联 FR、NFR、TC、ADR、DEC：待填写。
- 前置决策与阻塞：待填写。

### 验收条件

- [ ] 预期行为有可检查的结果。
- [ ] 失败路径及边界有说明。
- [ ] 仅使用合成样例验证。
- [ ] 隐私、授权、删除及文档影响已评估。

将上面的通用项替换或补充为具体判据，未验证项保持未勾选。

### 方案与验证计划

写出选择理由、备选及取舍，说明如何以合成数据验证；不提供真实患者材料。涉及数据模型、日志、供应商或同意变化时，明确影响及需确认的 DEC。

### 目标产出与下一步

产出名称、责任人、依赖和预计检查点：待填写。

## 4. 缺陷 Issue 模板

### 现象与影响

用清楚的步骤描述现象、预期行为和实际行为。说明是否阻塞上传、确认、图表、删除或账号访问。

### 复现条件

- 产品版本与移动浏览器类别：待填写。
- 合成样例和最小复现步骤：待填写。
- 出现频率、影响范围：待填写。
- 已脱敏的错误类别或关联号：待填写。

### 修复验收

- [ ] 原合成场景可通过。
- [ ] 相邻失败或边界路径已检查。
- [ ] 未引入跨账号访问、日志泄露或生命周期回退。
- [ ] 对应 TC 与文档已更新。

### 安全问题特别说明

疑似泄露、越权、凭据暴露问题通过待确认的人工安全渠道报告，不在公开 Issue 粘贴原始证据。渠道未确定前由项目发起人明确接收方式，不能为排障要求公开真实报告。

## 5. PR 说明模板

### 问题与变化

先写具体问题和变更后的行为，必要时给出合成场景的前后对比。按最终范围重写说明，不保留与评审无关的讨论过程。

### 关联与范围

- 关联 Issue、FR、NFR、TC、ADR、DEC：待填写。
- 目标版本、受影响页面或文档：待填写。
- 是否影响授权、数据结构、供应商、删除或恢复：待填写。

### 验证证据

| 验证项目 | 合成场景或评审方式 | 实际结果 | 未验证原因及发布影响 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 待填写 |

### 评审清单

- [ ] 变化属于已确认范围，新增决策已记录。
- [ ] 无真实患者数据、秘密及敏感日志。
- [ ] 草稿、确认、权限、分组和生命周期规则未被绕过。
- [ ] 相关成功、失败及边界验证有实际证据。
- [ ] 用户文档与版本说明和最终行为一致。
- [ ] 数据迁移、回退及恢复影响已说明；不适用时给出理由。
- [ ] 许可与第三方材料归属已检查；MIT 未确认时不称已采用。

### 已知限制与后续

写清仍未实现或未验证的部分、是否阻塞发布及关联 Issue。软件 License 不授权患者数据。提交、推送、合并等操作仍须逐项解释并获用户确认。
