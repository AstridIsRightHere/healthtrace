# 27 毕业论文摘要与伦理声明草稿

> 文档性质：设计阶段草稿。系统尚未据本文完成实现或实测，不得将计划写成已完成成果；伦理审批、豁免或备案结论均未在本文中作出。

## 1. 候选论文题目

面向成年人及授权家属代管的个人检验报告管理系统设计——基于 PWA 与人工确认的数据整理方案

题目待学校要求及最终研究范围确认。若后续确有实现和验证，应根据真实工作修改题目与摘要，不提前加入“实现”“应用效果”等完成性表述。

## 2. 中文摘要草稿

个人及家庭在长期保存检验报告时，可能面临纸质与图像资料分散、历史结果难以检索、不同单位和参考范围难以直接比较等问题。本研究拟设计 HealthTrace 个人检验报告管理系统，面向具有自主授权能力的成年人，以及经本人授权的成年子女或配偶代管场景，探索以报告整理、逐项核对和历史展示支持个人信息管理的方案。

系统拟采用 Vue PWA、Spring Boot 单体服务与 MySQL 数据库。最小可用版本计划采用单账号单患者的使用边界，并在数据库设计中为未来多档案扩展作准备。拟设计的处理流程包括多图归并为单份报告、历史补录、OCR 草稿、拒绝 OCR 时手工录入、逐项人工确认、待处理任务和修改审计；仅已确认的正式结果进入图表。指标展示拟按单位、检测方法及标本差异分组，不进行自动单位换算；参考范围取自对应报告，非精确结果保留于列表，对单点、前值为零和同日先后不明等情形给出明确展示或计算限制。

在隐私与安全方面，拟采用邀请码、邮箱密码及邮箱验证流程，并限制未验证账号的真实上传与找回能力；代管基于授权声明及时间戳，画像不参与权限授予，管理员默认不能查看健康内容。设计同时区分列表移除、彻底删除、账号注销与授权撤回，规划必要安全和运行日志、恢复演练以及境内供应商数据处理边界。开发与初步验证拟仅使用自行构造的合成数据，后续可根据已确认的功能与非功能验收条件检查流程正确性、权限隔离、移动端易用性和恢复能力。本阶段形成的是需求、架构与验证方案，不包含系统已实现、真实报告识别准确率、临床有效性或用户效果的实测结论。

## 5. 伦理声明草稿

### 5.1 当前数据与研究对象边界

本项目设计阶段的开发、演示、截图、测试及论文示例仅拟使用自行构造的合成数据，不使用真实患者报告，不使用真实报告改名或简单去标识后的数据，不将家庭成员资料视为可以自由用于研发的材料。合成数据不代表真实疾病、临床分布或患者行为。

当前草稿不宣称已获得伦理审查批准或豁免。是否需要伦理审查、备案或其他研究批准，应由所在学校或适用机构依据最终研究方式判断；具体结论需有可核查依据后才能写入正式论文。

### 5.2 授权与自主决定

目标场景限于具有自主授权能力的成年人。子女或配偶代管需本人有效授权，家属关系本身不自动产生权限；系统拟记录家属授权声明和时间戳，但该设计不能替代适用法律对有效授权的要求。授权撤回、解除代管及患者接管应有清晰核验路径，接管规则待 DEC-013，人工渠道待 DEC-016。

若未来拟开展家庭试用，应在开始前单独评估研究目的、参与者招募、自愿同意、健康信息处理、撤回后处置、风险、供应商数据流及学校要求。不得把本草稿当作真实数据试用授权，也不能用亲属关系替代参与者同意。

### 5.3 健康数据与外部处理

真实上线前应确认境内 OCR、对象存储与邮件供应商的合同、处理目的、必要字段、不用于训练约定、留存和删除边界，并完成适用告知、同意及备案评估。邮箱未验证用户可以登录，但不能真实上传或找回；人工核实不绕过验证。拒绝 OCR 的用户应能选择手工录入，并清楚了解原图、草稿及审计的生命周期。

管理员默认不查看健康内容；开发、排障与公开协作不使用真实健康数据。运行日志只保留必要安全和运行信息，不记录数值、指标名称、患者检查日期、图片、邮箱全文或 OCR 全文。MVP 不启用第三方分析；匿名计数仅为 v1.1 候选，不能将去标识等同于不可识别。

### 5.4 删除、撤回与恢复

系统拟区分列表移除、彻底删除、注销及撤回授权，向用户说明各自影响和人工办理方式。实际响应期限、备份及供应商残留处理尚待 DEC-002、DEC-003 和 DEC-005 确认，不承诺即时抹除全部副本。恢复演练应检查已删除数据与已撤回权限不会重新可用。

### 5.5 非医疗用途与结果表达

系统仅拟帮助整理和展示个人记录，不提供诊断、治疗或用药建议。参考范围、增减和趋势展示不能据此认定疾病变化或治疗效果；不同单位、方法和标本的结果不自动等同。论文不得把界面展示或合成样本表现解释成临床有效性。

### 5.6 公开材料与许可

公开仓库仅包含可公开的文档、代码与自造合成数据，不含患者资料和真实密钥。MIT 是待确认的许可候选；任何软件或文档 License 都不授权患者数据的使用、传播或训练。引用、第三方依赖和图表来源应遵守相应许可及学术规范。

## 6. 后续论文补写要求

正式论文应按实际进展区分设计、实现、测试和讨论。只有完成且留有记录的工作才能改成完成时态；实验需提供环境、样本、方法、指标、结果和局限，不补造样本量、识别率、性能或用户评价。毕业论文题目、引用格式、摘要字数及伦理声明用语以学校要求为准。

工期规划每周 8–12 小时、约 3–5 个月只用于项目安排，不构成研究完成保证。每个迭代回顾、每 4 周检查一次，必要时缩小研究范围并说明原因。
