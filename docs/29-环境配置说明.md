# 29 环境配置说明

## 目标、产出与下一步

目标：说明开发、测试、生产三套配置边界，避免测试代码或凭据接入真实数据。产出：差异表、秘密管理及核对清单；不含配置文件、真实值或运行命令。状态：第二阶段建议稿。下一步：评审DEC-025后，编码阶段再形成经审查的配置模板。

## 三套逻辑环境

三套是逻辑隔离要求，不强制租三台服务器。开发与测试可在个人电脑分时或隔离实例运行；生产仅启用正式批准资源。共享宿主不能共享数据库、存储前缀、密钥或登录会话，需防止误连；若无法证明隔离则不接真实资料。

| 配置类别 | 开发 | 测试 | 生产 |
| --- | --- | --- | --- |
| 数据 | 自造合成数据、可重建 | 版本化合成集与独立账号，执行后按规则清理 | 批准后真实资料；不得复制到开发测试 |
| 数据库 | 本地独立实例/库，显式环境标识 | 独立MySQL测试实例，验证与生产兼容版本 | 内部可达、持久化、备份、最小业务权限；迁移身份分开 |
| 对象存储 | 本地替身或专用测试位置 | 独立私有桶/受控空间，模拟失败 | 境内私有存储、鉴权访问、生命周期与备份核实 |
| OCR | 默认替身；合成样本受控契约测试 | 默认替身故障注入；合成集限额评测 | 审查通过的境内服务、当前同意、费用上限与关闭外发能力 |
| 邮件 | 捕获到本地测试设施，不向真实收件人发送 | 替身验证成功/失败/令牌失效 | 批准发信域名与供应商，验证/恢复用途，无健康内容与跟踪 |
| 域名与HTTPS | 本机地址；必要安全Cookie测试使用受控HTTPS | 独立测试地址/浏览器环境，不映射到生产 | 自有域名HTTPS、证书续期提醒及适用备案核实 |
| 会话/CORS/CSRF | 安全测试专门验证，任何便利开关只在隔离环境 | 尽量与生产规则一致，覆盖失效与跨账号 | 同源候选、最小来源、CSRF防护，不启用通配来源与调试绕过 |
| 日志 | 只记录必要脱敏信息，仍禁止医疗内容/凭据 | 合成环境检查错误路径泄露 | 最小安全/运行日志、受限访问与批准留存期限 |
| 资源/任务 | 小配额与易观察错误 | 模拟超时重试、容量与重启 | 有限重试与并发、容量和成本告警，参数待DEC确认 |
| 备份恢复 | 可重建；验证机制使用合成集 | 一致快照与删除账本隔离演练 | 批准频率、境内异地加密、密钥恢复与删除后禁复活 |
| 调试/管理 | 开发功能不可绕过生产门槛 | 覆盖管理负例与安全默认值 | 关闭调试详情、数据库控制台与公共管理端点；管理员默认不可看病历 |

未验证账号门禁、逐项确认、权限隔离等业务规则三套一致；若需要体验功能，使用明确隔离的合成演示而非开放真实上传后相信用户自觉。测试邮件替身不能成为生产绕过邮箱所有权验证的开关。

## 开发工具与缓存路径约定（Tools与Caches分离）

（2026-10-24 编码阶段确认）项目发起人的本机开发环境按“工具本体”与“依赖/缓存”分离放在 D 盘，任何依赖下载、构建缓存与容器镜像均不写入 C 盘系统盘。此约定只描述本机目录规划，不含秘密，也不约束测试/生产环境。

| 目录 | 用途 | 配置方式 |
| --- | --- | --- |
| `D:\Development\Tools\` | 环境/工具本体：JDK 21、Maven、Node.js 等 | 安装时选择该路径，并加入 PATH |
| `D:\Development\Caches\npm-cache` | npm 下载缓存 | `npm config set cache` |
| `D:\Development\Caches\npm-global` | npm 全局安装目录 | `npm config set prefix` |
| `D:\Development\Caches\m2-repository` | Maven 本地仓库 | 用户级 `~/.m2/settings.xml` 的 `<localRepository>`，或命令行 `-Dmaven.repo.local=` |
| `D:\Development\Caches\Docker-data` | Docker Desktop 虚拟磁盘（含 MySQL 镜像与数据卷） | Docker Desktop → Settings → Resources → Disk image location |

- 本机路径属于个人环境配置，不写入仓库内的 `pom.xml`、`.mvn/` 或 `package.json`，以免影响其他协作者和 CI。
- 不使用 Maven Wrapper（mvnw），避免把 Maven 本体下载到用户目录。
- 执行 `npm install`、`mvn package`、`docker pull` 前，可用 `npm config get cache`、`mvn help:evaluate -Dexpression=settings.localRepository` 和 Docker Desktop 磁盘设置核对路径。

## 配置与秘密分类

| 类别 | 内容 | 保存规则 |
| --- | --- | --- |
| 非秘密参数 | 环境名、端口规划、限额、任务超时、依赖版本 | 可公开说明，真实网络拓扑按必要性最小披露 |
| 秘密 | 数据库密码、会话/加密密钥、邮件/OCR/对象凭据 | 独立受控秘密位置或部署秘密机制，按环境分开；不进入Git/截图/CI普通变量输出 |
| 业务数据 | 报告原图、OCR、用户邮箱及授权信息 | 不是配置，不可作为示例值或夹在环境文件里 |

启动配置校验建议拒绝缺失关键秘密、测试供应商误连生产、生产关闭CSRF/HTTPS保护等危险组合，不能静默回退到默认密码。环境标识与存储命名有可核对关系；配置覆盖顺序在实现时明确并记录，不依赖个人记忆。

秘密轮换记录影响、时间与验证，不记录秘密本身；加密密钥轮换需保留合法存量数据解密路径和受控备份恢复资料，不能随意换键导致数据不可读。生产访问身份与CI检查身份分离，发布不把服务器全部权限给PR。

## 发布前配置核对

- [ ] 目标环境、数据库与存储明确且互不混用；生产连接不是开发默认值。
- [ ] 依赖/迁移版本与产物匹配，生产迁移具备受控身份和可恢复资料。
- [ ] 邮件/OCR服务商、地区、训练/留存条款、配额与必要同意均通过。
- [ ] Cookie/CSRF/来源限制、HTTPS、管理员权限与脱敏日志按测试证据验证。
- [ ] 域名证书到期、备份与最小删除账本、告警和人工响应渠道可用。
- [ ] 真实凭据不在仓库、构建产物或日志中；配置审阅仅展示脱敏摘要。
