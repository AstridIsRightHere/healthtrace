# 32 UI原型与设计规范

## 目标与范围

本文档记录 HealthTrace 四大核心页面的低保真原型及设计规范，覆盖布局结构、组件层级、交互模式与视觉风格。目标：确保温馨、圆角、低对比度的设计语言一致性，降低代管者认知负担。

设计规范基于已实现的 AppLayout 全局导航框架（PR #27），扩展至档案、时间线、我的三个核心 Tab 及其二级页面。

---

## 1. 设计原则

### 1.1 视觉风格
- **温馨简洁**：暖色背景、圆角卡片、柔和阴影，避免冷硬的科技感
- **低对比度**：文本与背景对比满足 WCAG 2.2 AA（≥4.5:1），但不使用纯黑纯白
- **圆角统一**：卡片 20px，输入框与按钮 12px，小标签 8px
- **间距律动**：卡片间距 24px（移动端 20px），内容区段间距 16px

### 1.2 交互原则
- **触控友好**：所有可点击目标 ≥44×44 CSS px（项目基线，严于 WCAG AA）
- **状态清晰**：当前激活项用背景色+文字+`aria-current`标注，不依赖颜色单一编码
- **渐进披露**：首屏展示核心操作，次要功能折叠或置于二级页面
- **容错反馈**：错误提示可见文本+`aria-live`，成功操作显示 Toast 确认

### 1.3 可访问性
- 键盘可达：Tab 顺序符合视觉顺序，焦点框 3px `var(--focus)`
- 屏幕阅读器：语义化标签、`aria-label`、表单关联、状态通知
- 缩放支持：200% 缩放下布局不破坏，内容可访问
- 主题支持：浅色、深色、跟随系统（MVP 仅浅色已实现）

## 2. 色彩系统

### 2.1 基础色板（浅色主题，已实现）
```css
:root {
  --bg: #fdf8f3;           /* 页面背景，暖米色 */
  --card-bg: #ffffff;      /* 卡片背景，纯白 */
  --text: #5c5149;         /* 正文，棕灰 */
  --text-h: #2f2722;       /* 标题，深棕 */
  --muted: #8a7d73;        /* 次要文本，浅棕 */
  --border: #eadfd5;       /* 边框，米色 */
  --accent: #e07a5f;       /* 主色调，暖橙 */
  --accent-hover: #c9664c; /* 主色悬停 */
  --accent-soft: rgba(224, 122, 95, 0.12); /* 主色半透明 */
  --focus: #3d7ea6;        /* 焦点框，蓝色 */
  --shadow: 0 12px 32px rgba(92, 81, 73, 0.1); /* 卡片阴影 */
}
```

### 2.2 语义色（状态反馈）
```css
--success-bg: #ecf6ee;
--success-text: #2e6b3c;
--error-bg: #fdeeee;
--error-text: #a33a3a;
```

### 2.3 按钮色彩
- **主操作** `.btn-primary`：白色文字 + `var(--accent-hover)` 背景
- **次要操作** `.btn-secondary`：深色文字 + 白色背景 + 边框
- **温和次要** `.btn-ghost`：灰色文字 + 浅色背景，无边框
- **危险操作** `.btn-danger`：白色文字 + `#b42318` 背景（彻底删除、注销）

## 3. 字体与文本

### 3.1 字体栈
```css
--sans: system-ui, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif;
```

### 3.2 字号层级
- **基础正文**：16px / 1.6（line-height）
- **标题 h1**：26px / 600 weight
- **次级标题**：18–20px / 600 weight
- **小标签**：14px（表单提示、时间戳）
- **用户可调**：14 / 16（默认）/ 20 / 24 px（MVP 未实装）

## 8. 响应式布局

### 8.1 断点
- **移动端**：`< 960px`
  - 底部 Tab 栏固定，高度 64px + `safe-area-inset-bottom`
  - 内容区 `padding-bottom: 104px`（预留导航高度）
  - 卡片间距收紧为 20px
  
- **桌面端**：`≥ 960px`

## 10. data-testid 规范

所有交互元素必须提供 `data-testid`，用于 Playwright E2E 测试：

| 元素类型 | 命名规则 | 示例 |
|---|---|---|
| 页面容器 | `{page-name}-page` | `records-page`, `timeline-page` |
| 列表容器 | `{list-name}-list` | `records-list-structured`, `timeline-axis` |
| 列表项 | `{item-name}-item` | `report-item`, `timeline-entry` |
| 按钮 | `{action}-btn` 或 `{scope}-{action}` | `records-upload-imaging`, `visit-reports-add-btn` |
| 链接 | `{target}-link` | `recycle-link`, `settings-link`, `report-back-link` |
| 输入框 | `{field-name}-input` | `upload-conclusion-input`, `upload-hospital-input` |
| 对话框 | `{name}-dialog` | `report-select-dialog`, `manage-follow-dialog` |
| Tab 切换 | `{scope}-tab-{value}` | `records-tab-structured`, `records-tab-imaging` |
