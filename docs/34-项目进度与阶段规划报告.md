## 一、当前项目阶段定位

**结论：MVP 的“上传 → 识别/手填 → 逐项确认 → 趋势/对比 → 就诊时间线”核心数据闭环已在开发环境跑通；MVP 范围尚未全部完成，项目处于“MVP 开发后期”，还没有进入内测或生产部署准备。v1.1 尚未开始。**

依据：

1. 代码进度。2026-10-24 进入编码，至 2026-11-05 共合入 25 个功能/修复 PR（#5～#29）。后端 8 个模块、16 个 Controller、Flyway V1～V12 共 19 张表；前端 15 个页面视图、21 个组件。
2. 测试进度。后端 39 个测试类、`mvn verify` 410 个测试通过，其中 6 个 Testcontainers MySQL 8.4 集成测试；前端 13 个 Vitest 文件 87 个用例；GitHub Actions CI 在每个 PR 上运行。近期每个功能 PR 附有 Playwright 390/1280 px 本地 E2E 自测报告（脚本在仓库外，见第三部分 2.4）。
3. MVP 缺口。FR-009 临时指标与归并、FR-017 人工撤回授权、FR-018 管理员能力，以及 NFR-006 的主题/四档字号尚未实现（详见第三部分）。
4. 上线门槛。docs/21 §5 的八项发布门槛中，恢复演练、隐私与 OCR 说明、人工撤回说明仍没有证据；没有部署环境、备份方案落地、供应商合同和备案。主验收 TC 全部处于“未执行”。

对应 docs/11 的迭代划分：I1（身份与档案）、I2（报告闭环）基本完成；I3（趋势与就诊）除临时指标外完成；I4（权利与上线）完成了删除、注销、审计部分，加密备份、域名 HTTPS、回滚演练未开始；I5（有限试用）未开始。

### 3.2 P0 / P1 / P2 技术债

**P0（影响正确性或上线）**

- 生产部署链路空白：无生产配置、域名 HTTPS、反向代理、发布与回滚流程（docs/17、docs/28 仍是设计）。
- 备份未落地：无加密快照、异地副本、恢复演练和删除账本重放验证（docs/18，DEC-003 待定）。
- 删除未覆盖备份与 OCR 供应商副本（NFR-011 只完成主库和本地对象存储）。
- 存储只有 `LocalStorageService`，生产对象存储及其加密、权限未实现（DEC-005）。
- 首页待处理列表只提供“彻底删除”，“移入回收站”只在报告详情页，误删风险高（PR #29 已登记）。

**P1（影响性能、可维护或体验）**

- 前端包体积：ECharts `BaseChart` chunk 约 537 kB（gzip 约 181 kB），超出 Vite 500 kB 警告线；需按需拆分或懒加载。
- 数据库：`observation` 缺 `profile_id` 冗余列及对应索引，趋势查询需联表；指标 ID 列无外键约束。
- DEC-009 五项性能阈值没有任何实测记录（首屏、API、OCR、图表、列表）。
- 无测试覆盖率统计（后端无 JaCoCo，前端无 coverage 配置），无法给出覆盖率数字。
- Playwright E2E 脚本保存在仓库外（本机 `D:\Development\HealthTrace-Local\e2e`），未进入 CI，曾因目录丢失重写过一次。
- 前端视图无组件测试，Vitest 只覆盖纯函数和 1 个组件。

**P2（改进项）**

- OCR 手动重新识别次数上限、长期退避、供应商限流应对待定（DEC-026）。
- audit_event 没有明细列，报告元数据修改无法记录前后值（PR #29 已说明）。
- docs/23 §5 的 P2-13～17 文档项（content_digest 按档隔离、列表移除后图表行为等）。
